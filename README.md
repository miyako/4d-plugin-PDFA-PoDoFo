# 4D Plugin: PDF to PDF/A-3 (PoDoFo)

Converts PDF documents to PDF/A-3 format for Factur-X / ZUGFeRD compliance.

## What is Factur-X?

Factur-X is a Franco-German hybrid e-invoice standard (identical to ZUGFeRD 2.x). It combines a human-readable PDF with a machine-readable XML file embedded within a single PDF/A-3 document.

This plugin handles the first step: converting a standard PDF (e.g., from 4D's `SET CURRENT PRINTER` → Quartz/Print-to-PDF) into a PDF/A-3 compliant document.

## Syntax

```4d
$result:=PDF TO PDFA($inputPath; $outputPath)
```

| Parameter | Type | Description |
|-----------|------|-------------|
| `$inputPath` | Text | POSIX path to input PDF |
| `$outputPath` | Text | POSIX path for output PDF/A-3 |
| `$result` | Object | Status object |

### Return Object

```json
{
  "success": true,
  "code": 0,
  "message": "PDF/A-3 conversion successful"
}
```

## How It Works

Uses the [PoDoFo](https://github.com/podofo/podofo) library (LGPL-2.0+) to:

1. Load the input PDF
2. Add XMP metadata declaring PDF/A-3B conformance
3. Embed an sRGB ICC color profile as OutputIntent
4. Save the modified document

This approach works well when the input PDF is already "clean" (embedded fonts, RGB color space) — which is typically the case for PDFs generated by 4D's printing system via Quartz (macOS) or Microsoft Print to PDF (Windows).

## Building from Source

### Prerequisites

- CMake 3.15+
- C++17 compiler
- 4D Plugin SDK (included as submodule)
- PoDoFo library:
  - macOS: `brew install podofo`
  - Windows: `vcpkg install podofo:x64-windows-static-release --overlay-triplets=vcpkg-triplets` (static libraries + static CRT, so the `.4DX` needs no extra DLLs)

### Clone

```bash
git clone --recursive https://github.com/miyako/4d-plugin-PDFA-PoDoFo.git
```

### Build (macOS)

```bash
cd PDFA
mkdir cmake-build && cd cmake-build
cmake .. -DCMAKE_BUILD_TYPE=Release
cmake --build .
```

### Build (Windows)

```bash
cd PDFA
mkdir cmake-build && cd cmake-build
cmake .. -A x64 -DCMAKE_TOOLCHAIN_FILE=path/to/vcpkg/scripts/buildsystems/vcpkg.cmake -DVCPKG_TARGET_TRIPLET=x64-windows-static-release -DVCPKG_OVERLAY_TRIPLETS=../../vcpkg-triplets
cmake --build . --config Release
```

## Versioning and releases

`VERSION` is the authoritative strict `X.Y.Z` version (no leading zeros).
`PDFA/Info.plist`'s `CFBundleVersion` must match it; there is no independent
build counter. The lifecycle migration aligns the stale source plist from
`1.0.0` to the existing `1.0.5` without a release-version increment. The tracked
prebuilt test bundle is deliberately unchanged. Manifest command IDs, the plist
schema version, PoDoFo/PDF versions, and deployment targets are not release metadata.

1. Run **Bump Version** on the desired branch and choose `bump`: `patch`, `minor`,
   or `major`. It validates and commits only `VERSION` and `PDFA/Info.plist` to
   that selected branch. The non-force, explicit branch push disables follow-tags;
   a concurrent branch update rejects the stale push. It creates no tag/release
   and does not start Build.
2. Run **Build** separately on the desired branch/ref. There are no typed inputs,
   only GitHub's ref selector. All checkouts use the event's immutable `github.sha`,
   not a moving branch or tag. Preflight rejects malformed/drifted source versions,
   an existing `vX.Y.Z` tag or published/draft release, and
   API/authentication/network errors before native builds start. The authenticated
   release listing includes drafts and all pages; only a successful, complete,
   well-formed listing with no matching tag means release absence. A failed page,
   malformed response, or listing 404 fails closed.
3. Windows static PoDoFo/CRT building and DLL verification precede the macOS
   arm64 PoDoFo build. Bundle export/resource checks, signing verification, ZIP
   and DMG notarization (both must be `Accepted`), and DMG stapling/validation must
   succeed. Verified ZIP/DMG packages are also retained as workflow artifacts.
   Only then does publication recheck availability, non-force push `vX.Y.Z`
   directly at the selected SHA with follow-tags disabled, and create a **new**
   release containing `PDFA-X.Y.Z.zip` and `PDFA-X.Y.Z.dmg`.

Build publication is serialized repository-wide across branches, without
cancelling an active run. GitHub concurrency may replace older pending runs;
it is not a FIFO release queue. There is no main-only publication restriction.
Existing tag/release state is never overwritten or deleted. Publication is not
atomic: a failed/ambiguous tag push needs remote inspection; a release/API/upload
failure after a successful tag push may leave a tag alone or a partial release.
Release creation uses a create-only REST request followed by uploads without
`--clobber`, rather than `gh release create`'s automatic draft-deletion cleanup.
Rerunning Build then fails preflight. Inspect the exact remote tag SHA, release
state, logs, and retained verified package artifacts, and manually complete only
the missing publication work after review. Do not delete/retarget tags or
overwrite assets to make a rerun pass.

Build is manual-only; tag pushes no longer start it. The separate **Build and
Test** workflow remains automatic for pushes to `main` and pull requests targeting
`main`. No signing/notarization secret names or native build dependencies change.

Focused local lifecycle regressions (no native builds, signing, or publication):

```bash
python3 -m pip install -r .github/tests/requirements.txt
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s .github/tests -v
actionlint
```

Tests use fixed version-independent fixtures, live source consistency checks,
isolated local Git remotes, and a full-suite rerun after bumping a temporary source
copy. No remote tag, release, or workflow is created by these checks.

### String ownership regression (macOS)

`returnStatus` owns the temporary JSON string passed to synchronous JSON Parse
(command 1218). The pinned SDK shallow-assigns that string into the input variable;
the helper disposes it once after parsing, without clearing the input alias again
or disposing the object returned to 4D.

```bash
git submodule update --init 4D-Plugin-SDK
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s .github/tests -p test_string_ownership.py -v
```

This compiles the actual status/path helpers and pinned SDK against a narrow host
shim, with ASan and UBSan, without PoDoFo, plugin builds or packaging. It checks
6,000 success/error status returns, exact ASCII/BMP/supplementary text and escaping,
single string cleanup, returned-object preservation, and null/allocated empty
string representations. Charset conversion returns bytes, as required by the SDK.
The original helper fails the live-allocation assertion on its first status return.
This is not a test in a real 4D host or a Windows host-crash reproduction.
The audited SDK is `4d/4D-Plugin-SDK` at
`cd97d1876d4258b56d2516e8ad2816f4ee93e0b5` (implementation header `rev: v14`,
API header `rev: v13`; not an upstream release identifier). The runner extracts
the helpers verbatim with unique boundary/signature assertions; it does not keep
a second implementation. `PDFA_OWNERSHIP_SOURCE` can select an original source
snapshot to reproduce the pre-fix failure with the same harness.

## Limitations

- PoDoFo adds PDF/A-3 metadata and ICC OutputIntent but does **not**:
  - Re-encode non-embedded fonts
  - Remove transparency
  - Convert unsupported color spaces
  - Validate the result against PDF/A specification
- For arbitrary input PDFs, consider using Ghostscript-based conversion instead
- Currently builds arm64 only on macOS (Homebrew PoDoFo is arm64); for universal binary, build PoDoFo from source
